## 二、修法（只改 `read_outputs`，与 `invoke` 同构）

```c
/* 改前：map 整个 resource，循环上界却是 tensor->size —— 两者不等即越界 */
src_map = pipe_buffer_map_range(context, res, 0, pipe_buffer_size(res), READ);
for (k = 0; k < etna_ml_get_size(subgraph, output_idxs[i]); k++) …

/* 改后：与 invoke（etnaviv_ml.c:908）完全同构 —— 映射范围 = 读取范围 = tensor 自己的 */
struct etna_ml_tensor *tensor = etna_ml_get_tensor(subgraph, output_idxs[i]);
src_map = pipe_buffer_map_range(context, tensor->resource, tensor->offset, tensor->size, READ);
for (k = 0; k < tensor->size; k++) …
```

**外加 idx 边界检查**（`idx >= n_tensors` 则跳过）—— 必须有，
因为 `etna_ml_get_tensor` 在越界时会 `calloc` 并**写入**该槽，等于往野地址写。

**不加 `min()` 截断**：前两处的教训是「改单点会把越界换成**静默错误数值**」。
resource 真不够大时 `pipe_buffer_map_range` 返回 NULL → `assert(src_map)` 明确失败（SIGABRT，可观测），
而不是野指针或错数。`else` 分支的 `pipe_buffer_read` 同样改成 `(tensor->offset, tensor->size)`。

## 四、我对这一轮结果的判断（先说清，免得又出现「不崩就算好」）

| 判据 | 预期 |
|---|---|
| ① 不崩 | **应达成**（越界读消除） |
| ② 接管数 | 应与 `675a1091` **持平**（ROFIX 不影响接管，只改回读路径） |
| ③④ 数值 | **未知** |

**必须说清的一点**：三个 `tsize` 全是 **5000 的整数倍**（305000=61×5000、610000=122×5000），
而 `bsize` 恰为 5000，且 `tensor->offset` **全为 0**。
这强烈指向 `etna_ml_tensor_offset`（`etnaviv_ml.c:212-223`）的批量重定位 ——
它把所有 `resource == old_res` 的 tensor 一律改成同一个 `size`/`offset`。

**所以 ROFIX 修的是「崩溃」，不保证修好「数值」**：
若 `tensor->size` 本身被改错（610000 而真实张量更小），改后可能变成
「map 610000 失败 → assert」而不是正确读取。
**这是个诚实的结果，不是失败**：把野指针换成可观测的明确失败，正是前两处教训的要求。
