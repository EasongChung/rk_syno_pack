## 2. 我在源码里找到的机制（请重点复核这一段）

`/root/clawtemp/mesa_src/etnaviv_ml_nn_v7.c:218-232`（`write_core_6`）：

```c
for (unsigned superblock = 0; superblock < superblocks; superblock++) {
   unsigned kernels_in_superblock = DIV_ROUND_UP(kernels_per_core, superblocks);
   if (superblock == superblocks - 1)
      kernels_in_superblock = kernels_per_core - kernels_in_superblock * (superblocks - 1);  // ← rem
   for (unsigned kernel = 0; kernel < kernels_in_superblock; kernel++) {
      unsigned out_channel = core * kernels_in_superblock + kernel
                           + superblock * DIV_ROUND_UP(kernels_per_core, superblocks) * cores_used;
      //                    ↑ 末批这里用的是 rem，不是 d
```

⇒ **末批的每核基址变成 `core*rem`（应当是 `core*d`）**。

### 由观测反推出的公式（全部与实测吻合）
- `kpc = kernels_per_core = ceil(C/8)`（`v7:193`，cores_used=8）
- `sb = superblocks = ceil(kpc/5)`（`calc_superblocks` + `v7:198`）
- `d = ceil(kpc/sb)`（`v7:220` 的 DIV_ROUND_UP）
- `rem = kpc - (sb-1)*d`（`v7:222-223`）

★ **自证**：用这四条 + 系数流长度公式
`bits/core = 8(zrl) + 16(kpc) + Σ_superblock kernels_in_superblock × (C_in×8 + 64)`
（权重 C_in 字节 + bias 32bit + 输出偏移 32bit），再 `align(.,64)`、×8 核 ⇒ coef_cache，
**7 个点的 coef_cache 全部逐字节命中**（122: 2112×8=16,896 / 196: 5120×8=40,960 /
220: 6400×8=51,200 / 240: 7488×8=59,904 / 244: 7872×8=62,976 / 260: 8896×8=71,168 /
280: 10112×8=80,896）⇒ ⇒ **我对系数流的模型是精确的**。

⇒ **⇒ 由此得到「越界」账**：末批写的 out_channel 上限 = `(sb-1)*d*8 + 7*rem + (rem-1)`，
超出 `output_channels` 的部分即越界通道数（上表末列）。
- 244：`(6*5*8) + 7*1 + 0 = 247` ⇒ 越界 4（244..247），越界读 976 B、越界写 10,000 B
  （与你上轮那张表的 244 行完全一致 ⇒ **你的算术我这边独立复现了**）。
- **但 122 越界 6 个通道、196/220/260 各越界 4 个通道，都不挂** ⇒ ⇒
  **⇒ 「越界大小」也不是判别量。**

⇒ ★ **在已测的 8 个点里，244 唯一独特点：`rem == 1`**（122:4、196:5、220:3、240:5、
**244:1**、260:3、280:5）⇒ ⇒ 这是我目前的头号候选。
