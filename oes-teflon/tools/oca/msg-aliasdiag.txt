## 二、静态定位的可疑代码（含一处我自己说错的地方）

`etnaviv_ml.c` 两个函数做批量元数据迁移：

```c
/* reference_tensor_with_offset，:198-224 —— 同时改 size 与 offset */
if (old_res) for (i...) if (etna_ml_get_resource(subgraph, i) == old_res) {
   pipe_resource_reference(&tensors[i]->resource, src->resource);
   tensors[i]->size = size;
   tensors[i]->offset = offset;
}

/* recreate_tensor，:226-246 —— ★ 只改 size，没有 offset 赋值 */
if (old_res) for (i...) if (etna_ml_get_resource(subgraph, i) == old_res) {
   pipe_resource_reference(&tensors[i]->resource, new_res);
   tensors[i]->size = size;
}
```

**⚠️ 更正**：我上一轮说「`recreate_tensor` 也有同样的一段」—— **错**。
它**只改 size 不改 offset**，这个**不对称本身就是一条线索**。
（我把这条更正写进了补丁的 STRUCT 注释，避免下一个人按「共性」去校验。）

调用点 `:540 / :552 / :562 / :569` = `CONCAT` / `SPLIT` /
**`NN` 且 `input_count > 1`（Add/Subtract）** / `BYPASS`。

**可疑点**：批量分支把「所有共享 `old_res` 的 tensor」一律改成同一组值，
但它们本该各自占据 `old_res` 的**不同段**。

**但我用静态推不出实测那组数的关系** —— 三个 `off_expected` 全是 5000 的整数倍
（305000=61×5000、610000=122×5000）、`bsize` 恰为 5000、`toff` 全为 0。
所以要运行时数据。
