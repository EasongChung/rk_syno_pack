## 二、第三处缺陷：已定位到指令级

设备回溯（**真符号，不是 `+0x` 假符号化**）：

```
fsguard.so(etna_ml_subgraph_read_outputs+0x188)   ← 崩在这里
fsguard.so(+0x8564c)                              ← 调用者（static，无符号）
  ← InvokeImpl → Subgraph::Invoke → delegate
```

我本地对 `675a1091` 反汇编，故障指令精确定位：

```asm
2307d0: blr  x6                  ← pipe_buffer_map_range()
2307d4: mov  x24, x0             ← x24 = src_map（返回值）
2307d8: cbz  x0, 2309c0          ← ★ 有 NULL 分支
2307e8: ldrb w0, [x24, w26]      ← ★★ SIGSEGV
2307ec: sub  w0, w0, #0x80
2307f0: strb w0, [x1, x26]       ← outputs[i][k] = src_map[k] - 128
```

对应 `etnaviv_ml.c:46`：`outputs[i][k] = src_map[k] - 128;`

**`src_map` 不是 NULL** —— NULL 分支跳到 `__assert_fail`（`mov w2, #0x432` + `bl __assert_fail`），
说明 assert 是**编译进去的**，会走 SIGABRT 而不是 SIGSEGV。
所以是 **`pipe_buffer_map_range` 返回了非 NULL 的野指针**。

### 嫌疑点（与前两处同构：拿外部 index 无边界检查地索引内部数组）

调用者反汇编，`output_idxs[]` / `is_signed[]` 的构造循环：

```asm
855f4: ldr  w1, [x1, x3, lsl #2]   ← outputs[j]（TFLite 侧给的 tensor index）
855f8: umull x1, w1, w4            ← × 112  (sizeof(struct etna_ml_tensor))
855fc: add  x7, x6, x1             ← 直接索引 dynarray —— ★ 无上界检查
85604: ldr  x7, [x7, #8]           ← tensor->resource
85618: str  x7, [x24, x3, lsl #3]  ← output_idxs[j] = 那个指针
```

若 TFLite 侧传入的 tensor index 与 subgraph 内部 dynarray 的 index 空间不一致，
这里就越界读出垃圾 `resource`，再传到 `pipe_buffer_map_range` → 野指针。

**但这只是「像」，不是结论。** 我不把静态推理当结论 —— 需要 addr2line 确认源码行。
