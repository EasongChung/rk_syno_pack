三、真正的根因（本地离线审计查出来的，不需要 CI）

`addr2line` 那条链是对的：`subsample etnaviv_ml_nn.c:424`，
调用链 `etna_ml_lower_convolution → strided_to_normal → reshape → subsample`。
但**越界不在 `in_z`，在 `map_in` 的步长**。

我把真机模型（`pertensor.tflite`，6 MB，从设备拉下来）逐算子解析，崩溃分区里有：

```
op#58   CONV_2D  input=[1,52,52,244]  filter=[244,3,3,1]  stride=2x2
op#153  CONV_2D  input=[1,25,25,488]  filter=[488,3,3,1]  stride=2x2
                  ↑ 输入 244/488 通道      ↑ filter 的 in_c（最后一维）= 1
```

算术严丝合缝：

| 步骤 | 值 | 出处 |
|---|---|---|
| `operation->input_channels` | **244**（取自**输入张量**） | `etnaviv_ml_nn.c:571` |
| `wdims_in[3]` | 244 | `strided_to_normal` |
| `map_in` 步长 | `3*3*244 = 2196` | `reshape` |
| 权重张量实际大小 | `244*3*3*1 = ` **2196** | filter 真实形状 |

⇒ **`out_channel ≥ 1` 时 `map_in` 就已越过张量末尾**，`subsample` 读越界 → SIGSEGV。
注意 `map_in` 的步长用了 `input_channels`，而张量只有 `in_c=1` 深 —— **两者不是同一个量**。

这也解释了为什么离线审计「7 个 stride=2 卷积 filter 字节数全部自洽」却仍崩：
自洽性检查是拿 `oc*ic*w*h` 跟 `num_elements` 比，**没检查 `input_channels` 与 `filter.in_c` 是否相等**。

四、所以修法是「**不接管**」，不是改系数排布

从 coeff 构造（`weights_map[input_channels][w][h]`）到 `strided_to_normal` 的整条路径，
都建立在「filter 深度 == 输入通道」这个**不成立**的前提上。
改单点只会把**越界**换成**静默错误数值** —— 那比崩更糟。

正确做法：让驱动识别这种算子并**拒绝接管**，回退 CPU。
这正是 `etna_ml_operation_supported` 的职责（它本来就拒绝 dilation 与 per-axis 量化）。

**新补丁：`patch-etnaviv-filter-shape-guard.py`**，注入点：

```c
if (!operation->conv.depthwise &&

   ML_DBG("filter in_c (%u) != input channels (%u)，回退 CPU\n", …);

```

- 目标文件 **`etnaviv_ml.c`**（不是 `ml_nn*.c`）；
