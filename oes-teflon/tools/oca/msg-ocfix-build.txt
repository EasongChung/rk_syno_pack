三、补丁本身：两个决定都是从代码里读出来的，不是猜的

1. **修正映射**：`core*kernels_per_core + 前序 superblock 累计偏移 + kernel`，去掉末尾多余的 `* cores_used`。
   - `kernels_in_superblock` 是「本 superblock 内的 kernel 数」，不是「一个 core 的 kernel 数」；
   - superblock 偏移**必须取累计值**，因为最后一个 superblock 的 kernel 数会被
     `kernels_per_core - DIV_ROUND_UP(...)*(superblocks-1)` 减少 —— 写成 `sb*kernels_in_superblock` 是错的。
2. **护栏用钳位（clamp）而不是 `continue`**：函数内 `append_bits(kernels_per_core, 16, ...)` 已把
   「每 core 槽位数」写进位流头，**跳过会让位流少槽而整体错位**。所以越界时钳到 `output_channels-1`，
   槽位数不变，且 `weights_map[out_channel]`、`biases[out_channel]` 都不再越界。

**只修 `write_core_interleaved` 一处**：同款公式在文件里另有 3 处
（`write_core_6` ×2、`write_core_sequential` ×1），属同一缺陷类，但**本轮没有任何真机证据**，
所以不把未验证的改动混进交付产物 —— 已记录为待修项。你如果觉得该一次修四处，
请在回信里说明理由，我评估后单独派一轮。
