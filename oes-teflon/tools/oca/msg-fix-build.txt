三、★ 更重要的：**根因已经静态证明，诊断构建可以让位给修复构建**

在你构建的同时，我把崩溃从崩溃栈一路推到了源码语句，**一行代码都没编译**：

2. 指令指纹（`ldrb` 逐字节 → `sub -[x19,#268]` → `madd *[x19,#132]` 累加）
   唯一对应 `etnaviv_ml_nn_v7.c` 的 `calculate_bias_correction()`；
3. 用 aarch64 布局精确算出 `struct etna_operation` 偏移，五个访问点
   `#128/#132/#260/#264/#268` **全部对上字段**；
4. **决定性对照**（同仓库，mesa-26.2.5）：

| 函数 | 位置 | depthwise → `input_channels=1` |
|---|---|---|
| `calc_weight_quant` | etnaviv_ml_nn.c:202-203 | 有 |
| `requantize_weights` | etnaviv_ml_nn.c:239-240 | 有 |
| **`calculate_bias_correction`（v7）** | **etnaviv_ml_nn_v7.c:114** | **无 ← 缺陷** |
| `calculate_bias_correction`（v8） | etnaviv_ml_nn_v8.c:170-171 | **有（上游 v8 已修）** |

**根因**：深度卷积权重形状是 `[1,kh,kw,out_c]`，每输出通道只有 `W*H*1` 个权重；
v7 却按 `W*H*input_channels` 扫描**并以此为步长**。本模型 DWCONV `W=H=3, in_c=24`
→ 越界倍数 **24×**：oc=0 刚好扫完 216 字节缓冲区，**oc=1 起点即越界** →
向前扫到不可达页 → SIGSEGV，撞到哪页取决于堆布局（**这就是非确定性的来源**）。
普通 CONV（权重 `[out_c,kh,kw,in_c]`）恰好不越界，所以**只由 DWCONV 触发**。
`nn_core_version==7` 才走 v7（`etnaviv_ml_nn.c:1290-1293`），我们设备正是 7。

⇒ **这是上游 Mesa 的缺陷，不是模型问题**。也请收回我之前那个「退化尺度导致崩溃」的判断（zp 只影响算术值）。
