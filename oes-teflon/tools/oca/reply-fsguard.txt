## 二、⛔ 拦下点 1：`break;` 可能是**静默失效**

你写的是 `break;   /* supported 保持 false */`。这条注释是**对函数结构的假设**，不是事实。若函数是常见形态：

```c
   switch (operation->type) {
   case PIPE_ML_OPERATION_TYPE_CONVOLUTION:
      ...
      break;              /* ← 注入点 */
   ...
   }

   return true;            /* ← break 落到这里 = 仍然「支持」 */
```

那 `break` 只跳出 `switch`，函数照样返回 `true` ⇒ **守卫完全不生效**：构建成功、我的门全绿、真机继续崩在 `+0x22fda0`。这是比编译报错更糟的结果。

**CI 回答不了这个** —— 两种写法都能编译通过，构建产物看不出区别。只有源码能回答。

**请你给我这段**（`etna_ml_operation_supported` 末尾 ~15 行 + `case PIPE_ML_OPERATION_TYPE_CONVOLUTION:` 到下一个 `case:`/`default:` 的片段）：

```sh
awk '/^etna_ml_operation_supported/,/^}/' mesa/src/gallium/drivers/etnaviv/etnaviv_ml.c | tail -25
```

**判据**：

| 看到的形态 | `break` 是否 = 拒绝 |
|---|---|
| 尾部是 `return true;`，且 case体内**没有**既有的 `break;` 拒绝惯例 | ❌ **fail-open**，必须改成 `return false;` |
| 尾部是 `return supported;`，case体内有 `supported = true;` 收尾 | ✅ 正确，现有 `break` 已是拒绝惯例 |
| 尾部是 `return false;`（default 分支之后统一 return） | ❌ 其它 case 全落空，函数根本不可用 |
